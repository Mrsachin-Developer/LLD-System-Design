# Low-Level Design & System Design

A structured learning journey into **Object-Oriented Programming (OOP),
SOLID principles, Design Patterns, Low-Level Design (LLD), and System
Design** through practical implementations in Java.

The goal of this repository is to develop the ability to design software
that is **maintainable, extensible, reusable, and reliable**---not
simply to write code that works.

------------------------------------------------------------------------

## 🎯 Learning Objectives

-   Strengthen core Object-Oriented Programming concepts.
-   Understand and apply SOLID principles.
-   Learn design patterns and when to use them.
-   Translate requirements into objects, classes, and relationships.
-   Create UML class and sequence diagrams.
-   Design extensible solutions to real-world LLD problems.
-   Understand design trade-offs, edge cases, and concurrency.
-   Build confidence for SDE technical interviews.

## 🛠️ Technology & Tools

-   **Primary language:** Java
-   **Core topics:** OOP, SOLID, Design Patterns, LLD
-   **Design tools:** UML, Class Diagrams, Sequence Diagrams
-   **Approach:** Conceptual understanding followed by practical
    implementation

## 🧠 Approach to Every Design Problem

Each problem will be approached systematically:

1.  **Understand the requirements** --- identify functional
    requirements, constraints, and assumptions.
2.  **Clarify the problem** --- ask questions before committing to a
    design.
3.  **Identify core entities** --- determine objects, responsibilities,
    and relationships.
4.  **Design the solution** --- create class structures and UML
    diagrams.
5.  **Apply design principles** --- use SOLID principles and patterns
    where they genuinely help.
6.  **Implement in Java** --- write clean, modular, testable code.
7.  **Handle edge cases** --- consider invalid input, failures, and
    concurrency where relevant.
8.  **Review trade-offs** --- explain alternatives, limitations, and
    possible extensions.
9.  **Refactor** --- improve the design while preserving expected
    behaviour.

The focus is on understanding **why** a design decision is made, not
memorising patterns or copying implementations.
